# 🧪 Testing Guide

Comprehensive testing documentation for PitchDeck Autopilot.

## Overview

This project has **multi-layered test coverage** including:

- ✅ **Unit Tests** - Pure functions, business logic
- ✅ **API Contract Tests** - OpenRouter integration with mocked HTTP
- ✅ **Integration Tests** - End-to-end CLI workflows with real files
- ✅ **Validation Guards** - Edge cases, error handling
- ✅ **Mutation Testing** - Test effectiveness verification

**Target Coverage: 85%+**

---

## Quick Start

### Run All Tests

```bash
./run_tests.sh
```

This runs the complete test suite with coverage report and audit.

### Run Specific Test Types

```bash

pytest tests/test_validation.py -v

```

## Test Categories

### 1. Unit Tests (Pure Functions)

**Files:** `test_text_cleaner.py`, `test_markdown_builder.py`

Tests pure business logic without external dependencies.

```bash
pytest tests/test_text_cleaner.py -v
```

**Coverage Target:** 95%+

**Key Tests:**
- Text cleaning and normalization
- Header/footer removal
- Line merging logic
- Markdown building
- Filename sanitization
- Confidence scoring

### 2. API Contract Tests

**File:** `test_ai_analyzer.py`

Tests OpenRouter API integration with mocked HTTP responses.

```bash
pytest tests/test_ai_analyzer.py -m api -v
```

**Key Features:**
- ✅ Real HTTP contract verification
- ✅ Mocked responses using `responses` library
- ✅ Retry logic testing (3 attempts)
- ✅ Error handling (401, 429, 500)
- ✅ JSON parsing and fallback
- ✅ Timeout simulation

**Example Test:**
```python
@responses.activate
def test_retry_on_timeout(sample_deck_text):
    # First two calls timeout, third succeeds
    responses.add(responses.POST, OPENROUTER_URL, body=Timeout())
    responses.add(responses.POST, OPENROUTER_URL, body=Timeout())
    responses.add(responses.POST, OPENROUTER_URL, json=success_response)
    
    result = analyze_deck(sample_deck_text, "test-key", max_retries=2)
    
    # Verify 3 attempts were made
    assert len(responses.calls) == 3
```

### 3. Integration Tests

**File:** `test_integration.py`

Tests complete CLI workflows with real file I/O.

```bash
pytest tests/test_integration.py -v
```

**Key Features:**
- ✅ Click's CliRunner (simulates real CLI invocation)
- ✅ Real PDF/PPTX file processing
- ✅ File system operations
- ✅ Output verification
- ✅ Error scenario testing

**Example Test:**
```python
def test_basic_pdf_analysis(cli_runner, sample_pdf_path, temp_dir):
    result = cli_runner.invoke(main, [
        sample_pdf_path,
        '--output-dir', temp_dir
    ])
    
    assert result.exit_code == 0
    assert "Analysis complete" in result.output
    # Verify output file was created
    assert any(f.endswith('_Brief.md') for f in os.listdir(temp_dir))
```

### 4. Validation Guards

**File:** `test_validation.py`

Tests edge cases, error handling, and boundary conditions.

```bash
pytest tests/test_validation.py -v
```

**Test Categories:**
- Input validation (empty, None, very long text)
- File system guards (permissions, long filenames, special chars)
- Data validation (null bytes, control chars, unicode)
- Concurrency (duplicate file handling)
- Error recovery
- Boundary conditions (zero slides, single slide, huge decks)
- Resource limits (memory, CPU)

## Mutation Testing

Mutation testing verifies that tests actually catch bugs.

### Setup

```bash
pip install mutmut
```

### Running Mutation Tests

```bash
# Run mutations on core logic
mutmut run

# Show results
mutmut results

# Show specific surviving mutants
mutmut show <id>
```

### Configuration

**.mutmut-config.py:**
- Targets core logic modules (text_cleaner, ai_analyzer, markdown_builder)
- Skips UI code and trivial functions
- Target: <5% mutant survival rate

### Interpreting Results

- **Killed**: Test caught the mutation ✅
- **Survived**: Mutation not caught ⚠️ (needs more tests)
- **Timeout**: Mutation caused infinite loop
- **Suspicious**: Unusual behavior

## Test Quality Audit

### Running Audit

```bash
python audit.py
```

### Audit Checks

The audit script verifies:

1. **Real User Events** ✅
   - Integration tests use real CLI invocation
   - File I/O operations use real files
   - API tests verify actual HTTP contract

2. **Console Errors** ✅
   - No unexpected warnings during tests
   - No unhandled exceptions
   - Clean test output

3. **Coverage** ✅
   - Overall coverage ≥85%
   - All critical paths tested
   - Branch coverage included

4. **Test Quality** ✅
   - Test markers used (unit, integration, api, slow)
   - Proper test organization
   - Fixture reuse

### Pass Criteria

- ✅ Real user events score ≥ 75%
- ✅ No console errors
- ✅ Coverage ≥ 85%
- ✅ <5% mutants survive (if run)

## Best Practices

### Writing Tests

1. **Arrange-Act-Assert** pattern
   ```python
   def test_example():
       # Arrange
       data = setup_test_data()
       
       # Act
       result = function_under_test(data)
       
       # Assert
       assert result == expected_value
   ```

2. **Use fixtures** for common setup
3. **Test one thing** per test function
4. **Use descriptive names** (`test_parse_empty_pdf_returns_empty_list`)
5. **Mock external dependencies** (API calls, file system)

### Test Naming

- **Class names**: `TestFunctionName` or `TestFeature`
- **Test names**: `test_specific_behavior_under_condition`
- **Good**: `test_sanitize_filename_with_special_chars`
- **Bad**: `test_1`, `test_function`

### Fixtures vs Mocks

- **Fixtures**: Reusable test data/setup
- **Mocks**: Replace external dependencies

## Troubleshooting

### Tests Fail on Import

```bash
# Make sure deckbrief is in PYTHONPATH
export PYTHONPATH="${PYTHONPATH}:$(pwd)"
pytest tests/
```

### PDF/PPTX Creation Fails

Install required libraries:
```bash
pip install reportlab python-pptx
```

### API Tests Timeout

Increase timeout in test:
```python
@pytest.mark.timeout(60)
def test_slow_api_call():
    pass
```

### Coverage Too Low

1. Run coverage with missing lines:
   ```bash
   pytest --cov=deckbrief --cov-report=term-missing
   ```
2. Identify untested lines
3. Add tests for those lines
